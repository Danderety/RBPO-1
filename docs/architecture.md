# Устройство приложения

## Компоненты

- `server.mjs`: HTTP API, SQLite, начальные данные, файловые упражнения и mock warehouse.
- `public/index.html`, `style.css`, `app.js`: адаптивный магазин без внешних библиотек и CDN.
- `data/shop.sqlite`: постоянная БД, появляется при первом старте.
- `data/public/receipt.txt`, `data/secret.txt`: публичный и условно приватный файловые fixtures.
- `data/uploads`: загруженные учебные файлы.
- `scripts/verify.mjs`: общая проверка сценариев; Windows и Bash-обёртки вызывают её.
- `tests/lab.test.mjs`: запуск проверки в отдельном процессе с временной БД.

## База данных

| Таблица | Поля | Использование |
|---|---|---|
| users | id, email, password, role, name | Аккаунты и роли; пароль намеренно plaintext |
| products | id, name, category, price, glyph | Каталог; целые цены в рублях для демо |
| orders | id, user_id, total, address, status, items | Заказы; items — JSON-строка снимка корзины |
| reviews | id, product_id, body | Отзывы о товаре |
| sessions | token, user_id | Сессии без срока действия |

Для денежных расчётов настоящего магазина используйте минимальные денежные единицы и строгую модель цены; текущие поля и доверие клиенту намеренно упрощены. Начальные заказы имеют пустой состав `[]`; новые заказы из интерфейса содержат позиции.

## Разделение ограничителей и уязвимостей

Ограничители: bind loopback, проверка Host/Origin, запрет выхода path за `data`, URL allowlist mock-сервиса, redirect:error, таймаут 2 секунды. Они нужны для области действия учебных упражнений, но не превращают процесс в песочницу ОС. Не добавляйте в `data` настоящие секреты или симлинки на них.

Уязвимости: отдельные маршруты и DOM-sink, помеченные `LAB:`, а также описанные в документации отсутствующие проверки. Исправление конкретного задания делается отдельно от ограничителей.

## Перспективы: упражнения ещё не реализованы

Текущий каталог содержит только описанные в восьми тематических файлах работающие слабости или реально отсутствующие защитные меры. Ниже — кандидаты на отдельные расширения, а не скрытые возможности текущего магазина.

| Тема | Как работает и проявляется | Влияние | Как исправлять | Что нужно для лаборатории |
|---|---|---|---|---|
| OS command injection | Данные подставляются в строку shell; метасимволы меняют команду | Исполнение с правами процесса | Аргументы без shell, отказ от запуска команд, строгая схема | Отдельный disposable контейнер без host mounts и сети |
| SSTI | Введённый текст компилируется как шаблон | Чтение данных, иногда исполнение кода | Данные отдельно от шаблона, безопасный renderer | Изолированный шаблонизатор и маркер результата |
| XXE | XML parser разрешает внешние сущности | Чтение файлов и SSRF | Запрет DTD/external entities | Отдельный XML importer и вымышленные fixtures |
| Небезопасная десериализация | Недоверенный объект активирует поведение при восстановлении | Изменение состояния, иногда RCE | Простые форматы и схема, отказ от исполняемых объектов | Контейнерный процесс без привилегий |
| NoSQL injection | Объект с операторами принимается вместо скалярного значения | Обход фильтров и входа | Валидация типов, построение запросов сервером | Собственная NoSQL БД в отдельном окружении |
| GraphQL field authorization | Resolver выдаёт поля без проверки роли | Чтение приватных полей через разрешённый root | Авторизация resolver/объекта, лимиты сложности | Реальный GraphQL API |
| JWT algorithm confusion | Сервер неверно выбирает алгоритм/ключ | Подделка токена | Фиксированные алгоритмы и ключи, aud/iss/exp | Отдельный JWT режим; текущие сессии не JWT |
| OAuth redirect flaws | Код авторизации отправляется на неверный redirect URI | Захват входа | Точный redirect allowlist, state, PKCE | Учебный IdP без настоящих аккаунтов |
| CORS с credentials | Origin отражается без проверки | Чтение ответов чужим origin | Точный allowlist, минимум credential доступа | Два учебных origin; текущий Origin-guard это блокирует |
| Cache poisoning | Неучтённый input влияет на общий кеш | Подмена ответов другим пользователям | Согласованные cache key и vary, запрет кеша приватного | Собственный reverse proxy и кеш |
| HTTP request smuggling | Proxy и backend по-разному разделяют запросы | Рассинхронизация запросов и доступа | Однозначный parser, отказ от неоднозначных заголовков | Изолированная двухкомпонентная HTTP-цепочка |
| DNS rebinding | Разрешённое имя начинает указывать на внутренний IP | Обход сетевых ограничений | Проверка всех разрешённых IP и реального соединения | Учебный DNS и закрытая сеть |
| Race condition | Две операции читают один остаток до записи | Двойное списание купона/остатка | Транзакции, атомарные проверки, уникальные ограничения | Учёт склада и конкурентный тест |
| Zip Slip | Пути архива выходят из каталога распаковки | Перезапись чужих файлов | Канонизация каждого пути, изоляция распаковки | Архивы только с fixture-файлами |
| Supply chain | Подмена зависимости или обновления | Код в сборке или процессе | Lockfile, проверка происхождения, минимизация прав | Локальный учебный registry, без публичных пакетов |

Для каждой новой темы сначала фиксируются границы, минимальное наблюдаемое доказательство и нормальный сценарий, затем код, отдельная карточка и тест. У этой версии нет зависимостей npm, XML, GraphQL, OAuth, proxy, кеша и shell-исполнения; нельзя считать их уязвимыми по одному названию темы.
